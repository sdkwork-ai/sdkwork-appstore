## 文档定位

本文档是「AI模型测评」分类下方的三个垂直行业测评模块的产品权威（Canon）。每个模块是独立的应用市场分类入口，挂在 PC 客户端左侧导航的「AI模型测评」之下，各自拥有独立的模块包、路由、分类种子与文案，可独立实现、评审与发布。

「AI模型测评」模块已建立多规格测评（multi-spec evaluation）范式：同一测评应用覆盖多个 AI 模型/Agent 规格，每个规格独立评分与评论，官方基准分（benchmark）与用户评分双源呈现。三个垂直模块复用该范式，并把测评对象下沉到行业场景：教育实验、文旅讲解、医疗卫生。

## 3. 教育实验应用模块

**定位。** 把 AI 测评范式下沉到教育实验场景：每个测评应用覆盖一组学段×学科的教育实验任务（虚拟实验操作、实验报告批改、实验设计辅导、学科问答），每个 AI 规格在任务集上独立评分与评论，服务教师备课、学生自学与教育机构选型。

**学段分类。** `k12-primary` 小学、`k12-junior` 初中、`k12-senior` 高中、`university` 大学（本科/高职）、`professional` 专业应用（职业培训/继续教育/行业认证）。K12、大学、专业应用是页面的三个一级筛选；K12 内部再按小学/初中/高中二级筛选。

**学科分类。** 数学、物理、化学、生物、科学（小学综合）、地理、信息科技、语文、外语、工程基础。学科为页面二级筛选与卡片徽章；策展数据按「学科 → 任务集 → 基准维度」组织，基准维度示例：实验操作仿真、实验报告批改、实验设计辅导、学科知识问答、安全规范提示。

**页面结构。** 模块 hero（徽章 + 标题 + 副标题）→ 学段/学科筛选 chips → 实验应用卡片网格。卡片：应用图标 + 名称 + 评分、学段徽章、覆盖学科 chips（超出折叠为 +n）、领先规格基准分与 #1 标记。

**详情面板。** 详情页渲染「学段×学科覆盖矩阵」面板：行 = 学段，列 = 学科，格 = 覆盖任务数与该格基准分；下方沿用每规格评分与评论流。

**策展种子内容（首发）。** K12 虚拟实验测评（`app-edu-k12-virtual-lab`）、大学物理实验测评（`app-edu-university-physics-lab`）、专业技能实训测评（`app-edu-professional-skills`）。

**角色与场景。** K12 教师（选实验测评工具、看班级适用学段）、大学实验课教师、职业培训讲师（专业认证方向）、学生（自学与实验预习）、教育信息化采购（批量选型）。

## 4. 文旅应用模块

**定位。** 文旅场景的 AI 测评与应用分发：覆盖旅游景点的智能导览、讲解与行程规划，以及文博场馆、城市漫游、非遗民俗、研学旅行。以「旅游景点」为旗舰场景，测评 AI 讲解的准确性与行程规划的可用性。

**场景分类。** `attraction` 旅游景点（旗舰）、`museum` 文博场馆、`citywalk` 城市漫游、`heritage` 非遗民俗、`study-tour` 研学旅行。

**旅游景点元数据。** 地区（省/市）、景区等级（5A/4A/3A）、主题（自然风光/人文古迹/遗址公园/主题乐园）。策展数据按「景点 → 讲解任务集 → 基准维度」组织，基准维度示例：讲解准确性、行程规划合理性、多语言讲解、文化知识覆盖、实用信息时效性。

**页面结构。** 模块 hero → 场景筛选 + 地区筛选 chips → 应用卡片网格。卡片：应用图标 + 名称 + 评分、场景徽章、覆盖景点数、地区徽章、领先规格基准分与 #1 标记。

**详情面板。** 详情页渲染「景点覆盖」面板：覆盖景区列表（名称 + 等级 + 地区 + 该景点讲解准确度），下方沿用每规格评分与评论流。

**策展种子内容（首发）。** 景区智能导览测评（`app-tour-attraction-guide`）、行程规划测评（`app-tour-itinerary-planner`）、多语言讲解测评（`app-tour-multilingual-guide`）。

**角色与场景。** 游客（出行前选工具、行中扫码导览）、景区运营（选讲解系统）、文旅局/目的地营销（区域导览方案选型）、导游与研学导师（带团辅助）、旅行社（行程规划工具）。

**内容时效性。** 景区开放状态、票价与路线可能变化；策展基准数据标注采样周期，详情面板展示「数据更新于」时间戳，过期数据不宣称实时。

## 5. 医疗卫生应用模块

**定位。** 医疗卫生场景的 AI 测评与应用分发：覆盖临床辅助、公共卫生、健康管理、医药器械、医学教育五类场景，重点测评医学知识准确性、临床指南符合度与安全性（幻觉与危险建议控制）。

**场景分类。** `clinical` 医院与临床（辅助问诊/病历质控/护理）、`public-health` 公共卫生（疾控宣教/健康科普）、`health-mgmt` 健康管理（慢病/体检/康复）、`pharma-device` 医药与器械、`medical-edu` 医学教育与考核。

**测评维度。** 医学知识准确性、临床指南符合度、安全性（拒答与危险建议控制）、术语规范性、患者可读性。「安全性」维度在卡片与排行榜中单列展示，是本模块区别于其他模块的显著信号。

**页面结构。** 模块 hero → 场景筛选 chips → 应用卡片网格。卡片：应用图标 + 名称 + 评分、场景徽章、安全分徽章、领先规格基准分与 #1 标记。

**详情面板。** 详情页渲染「场景覆盖」面板：场景列表（该场景任务集与基准分，安全性维度单独一列），下方沿用每规格评分与评论流。

**合规展示。** 详情页固定展示非诊断免责声明（AI 输出不替代执业医师诊断与处方）；声明文案进 locale 词典，不可关闭。评论流沿用现有审核队列；新增举报理由「疑似诊疗建议」供用户标记处方/剂量类内容。

**策展种子内容（首发）。** 医学知识问答测评（`app-health-medical-qa`）、病历质控测评（`app-health-emr-quality`）、健康宣教测评（`app-health-health-education`）。

**角色与场景。** 临床医生（辅助工具选型）、医院信息科（院内采购评估）、医学院师生（教学与考核）、公卫机构（健康宣教材料）、健康管理用户（个人健康工具）。

**数据红线。** 模块本身不采集、不展示任何患者身份信息（PHI）；策展基准数据使用脱敏任务集；评论中出现的病情描述由现有审核流程处理。

## 6. 非功能与合规（三模块共用基线 + 行业附加项）

| 维度 | 共用基线 | 行业附加项 |
| --- | --- | --- |
| 安全 | 仅只读 storefront 面，IAM 沿用现有边界 | 无附加 |
| 隐私 | 模块自身不新增个人数据采集 | 教育：K12 内容适用未成年人保护要求；医疗：不引入 PHI |
| 性能 | 单分类窗口 ≤50 条，游标分页 | 无附加 |
| 可靠 | 分类缺失渲染显式空态 | 无附加 |
| 合规 | 年龄分级沿用 listing 分级字段 | 教育：适龄提示；医疗：非诊断免责声明固定展示 |
| i18n | 全部文案走 locale 词典（zh + en） | 医疗免责声明、教育适龄提示均需双语 |

## 7. 阶段规划

- **阶段一（本设计范围）**：PC storefront 三模块上线：模块包 + 侧边栏入口 + 路由 + 目录与上架种子 + i18n + 详情页垂直面板。
- **阶段二（非本设计承诺）**：纵向分类体系后端化（目录 API 增加属性维度）、H5 与移动端模块面、推荐与榜单接入、行业运营合集（编辑精选）。
- 每个模块独立排期与发布；模块间无实现依赖，允许分批上线。
